1. Graph search in one table

All four algorithms repeatedly take a waiting node, look at its neighbors, and add the new ones to the waiting set. They differ in which waiting node comes out next.

AlgorithmWaiting nodes kept inGuaranteeMemory
BFSFIFO queuePath with the fewest edgesO(V): a whole level can wait at once
DFSStack (or recursion)None for path lengthO(depth) along the current path
UCSPriority queue keyed by path costCheapest path, if all costs are non-negativeO(V)
IDDFSDepth-limited DFS, repeated with limits 0, 1, 2, …Path with the fewest edges, like BFSO(depth), like DFS

On an explicit graph, BFS and DFS take O(V + E) time. Two connections are worth remembering:

  • UCS is Dijkstra's algorithm that stops early, as soon as the goal is removed from the priority queue. Section 3 explains why that removal is final.
  • IDDFS repeats the shallow levels on every iteration, but when each node has at least two children the deepest level dominates the work, so the repetition costs only a constant factor. In exchange it keeps DFS's small memory.

2. Minimum spanning trees

Given a connected, undirected graph with edge weights, a spanning tree connects all V vertices with V − 1 edges and no cycle. A minimum spanning tree (MST) is one with the smallest total weight.

Cut property. Split the vertices into two sides S and V − S. A lightest edge crossing the split belongs to some MST. When all weights are distinct, it belongs to every MST, and the MST is unique.

Proof idea, an exchange argument as in Recitation 3: take an MST T that does not contain the lightest crossing edge e. Adding e to T creates a cycle, and that cycle must cross the split a second time through some edge f. Replacing f by e gives another spanning tree, and since w(e) ≤ w(f) its weight is no larger. So some MST contains e.

  • Prim grows one tree from a start vertex. The split is (tree, everything else), and each step adds the lightest edge leaving the tree. With a binary-heap priority queue it runs in O(E log V).
  • Kruskal scans all edges from lightest to heaviest and adds an edge whenever it joins two different components, so it never closes a cycle. The split for an accepted edge is one of its two components against everything else. Sorting costs O(E log E) = O(E log V). Checking whether two vertices are already in the same component needs a separate data structure (union-find, not covered in this recitation); with it, the checks add almost nothing and the total is O(E log V).

Neither algorithm cares whether weights are negative: the cut property only compares weights of edges that cross the same split.

3. Single-source shortest paths

Given a weighted directed graph and a source s, find the distance d(v) of the cheapest path from s to every vertex v. Both algorithms in this section keep a tentative distance d[v] (∞ at the start, 0 for s) and improve it with the same step, called relaxing the edge (u, v):

Pseudocode · relax
RELAX(u, v, w)
    if d[u] + w < d[v]:
        d[v] = d[u] + w     // the path to u, then edge (u, v), is cheaper

Dijkstra: finalize the closest vertex

Pseudocode · Dijkstra
DIJKSTRA(G, s)
    d[v] = ∞ for every vertex v;  d[s] = 0
    Q = priority queue of all vertices, keyed by d
    while Q is not empty:
        u = EXTRACT-MIN(Q)          // d[u] is now final
        for each edge (u, v, w):
            if v is still in Q:     // never update a final vertex
                RELAX(u, v, w)      // and decrease v's key in Q

Why removing u makes d[u] final: when u comes out, every other path to u has to leave the set of final vertices at some vertex x that is still in Q, and d[x] ≥ d[u] because u was the minimum. If all weights are non-negative, the rest of that path cannot make it cheaper than d[u]. With a binary heap, Dijkstra runs in O((V + E) log V).

Bellman-Ford: relax everything, V − 1 times

Pseudocode · Bellman-Ford
BELLMAN-FORD(G, s)
    d[v] = ∞ for every vertex v;  d[s] = 0
    repeat V − 1 times:             // one "round"
        for each edge (u, v, w):
            RELAX(u, v, w)
    for each edge (u, v, w):        // one extra check
        if d[u] + w < d[v]:
            return "negative cycle reachable from s"
    return d

Round invariant: after round i, d[v] is at most the cost of the cheapest path from s to v that uses at most i edges. Without a negative cycle, some shortest path repeats no vertex, so it has at most V − 1 edges, and V − 1 rounds are enough. If the extra check can still improve an edge, a negative cycle is reachable from s. Bellman-Ford runs in O(VE) time and handles negative edges.

Reference explanation · open after attempting

1. Kruskal. Sorted edges: A–C 1, B–D 2, B–C 3, A–B 4, C–D 5, D–E 6, C–E 8, D–F 9. It accepts A–C 1, B–D 2, and B–C 3. The first rejection is A–B 4, which would close the cycle A–C–B–A. It then rejects C–D 5 (cycle C–B–D–C), accepts D–E 6, rejects C–E 8 (cycle C–B–D–E–C), and accepts D–F 9. That is V − 1 = 5 edges. Total weight: 1 + 2 + 3 + 6 + 9 = 21.

2. Prim. Prim picks the same five edges (total 21), but in a different order: B–C 3 comes before B–D 2, because B–D does not cross Prim's split until B joins the tree. The trees must agree because all weights are distinct, so the MST is unique by the cut property.

3a. False. D–F 9 is the heaviest edge in this graph, and it is in the MST: it is the only edge reaching F, so every spanning tree must use it. The true statement is about cycles: with distinct weights, the heaviest edge on a cycle is never in an MST (A–B 4 and C–E 8 above are examples). An edge on no cycle, such as D–F, must be in every spanning tree, however heavy it is.

3b. True. Let e = (u, v) be the lightest edge. Take the split S = {u}. Edge e crosses it and is lighter than every other edge, so it is the unique lightest crossing edge and belongs to every MST. With ties the claim fails: in a triangle whose three edges all weigh 1, each MST leaves out one of the lightest edges.

3c. False. Triangle X–Y 1, Y–Z 1, X–Z 1.5. The MST is {X–Y, Y–Z} with weight 2, so its X–Z path costs 2, but the shortest X–Z path is the direct edge, 1.5. An MST minimizes the total weight of the tree, not the distance between any particular pair. That is why shortest paths need different algorithms.

1. Dijkstra finalizes S (0), A (2), T (3), B (5). When B comes out, B→A would give 5 − 4 = 1, but A is already final, so nothing changes. Dijkstra reports A = 2 and T = 3. The true distances are A = 1 (S→B→A) and T = 2 (S→B→A→T); S = 0 and B = 5 are correct.

2. The mistake is finalizing A at distance 2. The correctness argument says any other path to A leaves the final set through a vertex still in the queue (here B, with d[B] = 5 ≥ 2), and that the rest of the path cannot make it cheaper. That last step needs non-negative weights; the edge B→A −4 breaks it. T inherits the error because it was finalized from the wrong d[A]. Some textbook versions relax every outgoing edge, even into final vertices; they would change d[A] to 1 at the end, but T has already been finalized at 3, so the result is still wrong.

3. Round 1 in the given order: S→A sets A = 2, S→B sets B = 5, B→A lowers A to 1, A→T sets T = 2. Rounds 2 and 3 (V − 1 = 3 rounds in total) change nothing, and the extra check finds no improvable edge, so there is no negative cycle. The answers S = 0, A = 1, B = 5, T = 2 are correct. (The edge order made this graph finish in one round; another order could need more rounds, but never more than V − 1.)

Why V − 1 rounds suffice. By induction on i: if the cheapest path to v with at most i edges ends with edge (u, v), its first part reaches u with at most i − 1 edges, so after round i − 1, d[u] is at most that cost, and relaxing (u, v) in round i brings d[v] down to at most the full cost. Also, d[v] is always the cost of some real path, so it never drops below the true distance. With no negative cycle, cutting a cycle out of a path never makes it more expensive, so some shortest path repeats no vertex and has at most V − 1 edges. After V − 1 rounds every d[v] is exact.

Negative cycles. If no negative cycle is reachable, the distances are exact after V − 1 rounds and no edge can be improved, so the extra check passes. If a negative cycle v1 → ⋯ → vk → v1 is reachable and no edge on it could be improved, then d[vi+1] ≤ d[vi] + w(vi, vi+1) for every edge of the cycle. Adding these inequalities around the cycle, the d terms cancel and leave 0 ≤ (total cycle weight) < 0, a contradiction. So some edge on the cycle can still be improved, and the check reports it.

Exercise 3 · Cheapest route with at most k stops

Coding and explanation · about 18 minutes. There are n cities, numbered 0 to n − 1, and a list of one-way flights [from, to, price]. Return the cheapest total price of a route from src to dst that makes at most k stops, that is, uses at most k + 1 flights. Return −1 if no such route exists.

This is Bellman-Ford with k + 1 rounds instead of V − 1: by the round invariant from Section 3, after round t the distances account for every route with at most t flights. There is one catch. The textbook Bellman-Ford updates d in place, so a value improved early in a round can be used again later in the same round, and one round can chain several flights. That speeds up the unrestricted version, but here it would let a route use more flights than allowed. Each round must therefore read from a copy of the distances as they were at the start of the round.

  • 1 ≤ n ≤ 100; 0 to 10,000 flights; from ≠ to; each price is between 0 and 10,000; several flights may join the same pair of cities.
  • src and dst are valid cities, and 0 ≤ k ≤ n − 1. If src == dst, the answer is 0.
  • Every answer is at most 1,000,000, so a 32-bit integer is enough. In C, C++, C#, and Java the starter uses the largest int as ∞, so never add a price to an unreached city's ∞.
  • Do not modify flights. Target: O(k · m) time for m flights and O(n) extra space.

Hint 2 · Test the trap by hand

Explain your answer: why does reading from a copy guarantee that round t only adds routes with exactly one more flight? Why are k + 1 rounds the right number? Give the time and space. Finally, why would plain Dijkstra on price, ignoring the number of flights, fail on the trap example with k = 0?

Reference explanation and code · open after attempting

The copy. Claim: after round t, dist[v] is the cheapest price of a route to v with at most t flights. Round t reads only values from round t − 1, which describe routes with at most t − 1 flights, and adds exactly one flight to each; keeping the old value covers routes that are already short enough. So every value describes a route with at most t flights, and every such route is considered. Writing in place breaks the first half: a value updated earlier in the round already includes one round-t flight, and using it adds a second.

Rounds. At most k stops means at most k + 1 flights, so after round k + 1, dist[dst] is exactly the answer; one more round could allow k + 1 stops.

Cost. Each round copies n values and looks at all m flights, so the time is O(k · (n + m)), which is O(k · m) whenever there are at least about n flights. The extra space is two arrays of n integers, O(n), separate from the input.

Why plain Dijkstra fails. Dijkstra finalizes each city at its cheapest price regardless of how many flights that price uses. On the trap it finalizes city 1 at 100 and then city 2 at 200 through city 1, a two-flight route, and never revisits city 2. The answer for k = 0 is the more expensive direct flight, 500. Any fix has to track the number of flights as part of the state, which is what the rounds of Bellman-Ford do.

Optional practice answers

1. Edges S→A 1, A→B −2, B→T 1, and S→T 1. The shortest S→T path is S→A→B→T with cost 0. Adding 2 to every weight gives S→A 3, A→B 0, B→T 3 (total 6) against S→T 3, so Dijkstra on the shifted graph returns the direct edge, which costs 1 in the original graph. Shifting penalizes a path once per edge, so it favors paths with fewer edges and can change which path is shortest. (Johnson's algorithm, beyond this course, makes a correct reweighting by adding a different amount for each vertex.)

2. Let P be the MST path between u and v, let e be its heaviest edge, and suppose another u–v path Q uses only edges lighter than e. Removing e splits the MST into two parts, with u on one side and v on the other. Q starts on u's side and ends on v's side, so some edge f of Q crosses the split, and w(f) < w(e). Replacing e by f gives a spanning tree with smaller total weight, which contradicts minimality. So no path has a lighter heaviest edge.

Discussion notes

Prim's key is the weight of the single lightest edge connecting a vertex to the tree; Dijkstra's key is the total cost of a whole path from the source. Prim's correctness comes from the cut property, which only compares edges crossing the same split, so negative weights change nothing. Dijkstra's correctness needs the rest of a path to be non-negative.

The standard Bellman-Ford only needs the final distances to be correct, and an in-place round can only make progress faster, since every value is still the cost of some real path. Exercise 3 also limits the number of flights, so a round must not add more than one flight to any route.

Exit check: trust Prim. Its proof uses only the cut property, which holds for any weights. Dijkstra may finalize a vertex too early when a negative edge appears later, as in Exercise 2.

Extra · All-pairs shortest paths with Floyd–Warshall

Optional extra content

This section is provided by the TA for students who want to go further. It is not covered in lectures or on the final exam, and the core exercises do not depend on it. It solves all-pairs shortest paths as a dynamic program, using the same five steps as Recitation 3.

Why we need it

Sometimes we want the distance between every pair of vertices, for example to fill a distance table between cities. Running Dijkstra from every vertex is fast but fails with negative edges. Running Bellman-Ford from every vertex handles negative edges but costs O(V2E), which is O(V4) on a dense graph. Floyd–Warshall handles negative edges (but not negative cycles) in Θ(V3) time with three short loops.

The DP, step by step

Number the vertices 0 to n − 1.

  1. Subproblem. Dk(i, j) is the cost of the cheapest path from i to j whose intermediate vertices all come from {0, …, k − 1}. The endpoints i and j themselves may be anything.
  2. Key math function. The cheapest such path either avoids vertex k − 1, or passes through it exactly once (with no negative cycle, a shortest path never needs to repeat it). So Dk(i, j) = min( Dk−1(i, j), Dk−1(i, k − 1) + Dk−1(k − 1, j) ).
  3. Base case and order. D0(i, j) allows no intermediate vertex: it is the weight of the lightest edge i → j, 0 when i = j, and ∞ if there is no edge. Fill rounds k = 1, 2, …, n in order.
  4. Answer. Dn(i, j) allows every vertex, so it is the true distance. One n × n table updated in place is enough: during round k, the row and column of vertex k − 1 do not change, because going through k − 1 to reach k − 1 itself adds D(k − 1, k − 1) = 0.
  5. Cost. n rounds × n2 cells × O(1) work = Θ(n3) time, and Θ(n2) space. A negative value on the diagonal at the end means a negative cycle.
Pseudocode · Floyd–Warshall
FLOYD-WARSHALL(n, edges)
    D[i][j] = 0 if i = j, else ∞
    for each edge (u, v, w):
        D[u][v] = min(D[u][v], w)        // lightest parallel edge
    for k = 0 to n − 1:                  // now allow vertex k in the middle
        for i = 0 to n − 1:
            for j = 0 to n − 1:
                if D[i][k] + D[k][j] < D[i][j]:
                    D[i][j] = D[i][k] + D[k][j]
    return D

In the code, the loop variable k is the vertex being allowed, so iteration k turns Dk into Dk+1. Because ∞ is a large number in code, skip the update whenever D[i][k] or D[k][j] is ∞. Otherwise ∞ plus a negative weight could look like a real, finite distance.

Extra · Build Floyd–Warshall
