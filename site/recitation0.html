Terminal basics: a skill for every CS course

Most setup problems are not uv or Java problems. They come from typing a command in the wrong place, running it in the wrong folder, or not knowing why the shell cannot find a program. This part is not specific to CS301: systems, operating systems, networking and research projects all assume you can use a terminal. Work through sections A–G once, ideally in one sitting, before step 1.

Already comfortable?

If you can explain what pwd, cd .. and PATH mean, enable Zsh comments if needed and skip to the course setup.

A. Open a terminal and identify your shell

A terminal is the window. A shell is the program running inside it that reads what you type and runs it. A command is the line you type. Different shells use slightly different rules, which is why code blocks on this site are labeled Bash, Zsh, or PowerShell.

  • macOS: press Cmd+Space, type Terminal, press Return. The default shell is Zsh.
  • Windows: open the Start menu, type Terminal (Windows 11) or PowerShell (Windows 10). Use PowerShell; if the prompt does not start with PS, you are in Command Prompt, so open a PowerShell tab instead.
  • Linux: open your distribution's Terminal app (often Ctrl+Alt+T). The default shell is usually Bash.
  • Inside your IDE: VS Code has Terminal → New Terminal (Ctrl+`); PyCharm has View → Tool Windows → Terminal. This is the same shell, already started in the folder you opened. For this course, prefer it once your project folder exists.

The text before the cursor is the prompt. It shows that the shell is ready and usually which folder you are in. You type after it; you never type the prompt itself. Typical prompts:

ShellTypical promptEnds with
Zsh (macOS)alex@MacBook ~ %%
Bash (Linux)alex@laptop:~$$
PowerShell (Windows)PS C:\Users\alex>>, starts with PS

Zsh only: enable comments first

Commands on this site end with a # comment that explains them. Zsh does not accept comments at the prompt by default, so if your shell is Zsh, run this first in every new Zsh terminal. The explanation is on the next line because inline comments are not enabled yet. Bash and PowerShell users can skip this.

Zsh · run first
setopt INTERACTIVE_COMMENTS
# Enable comments in this Zsh session before copying the commands below

B. Read a command

A command is a program name followed by arguments, separated by spaces. Arguments that start with - are usually options (also called flags) that change how the program behaves. Everything after # is a comment for you and is ignored.

Bash / Zsh / PowerShell
uv python install 3.13 # Program: uv · arguments: python, install, 3.13
java -version # Program: java · option: -version

The shell runs the command when you press Return, prints its output, and shows a new prompt when it finishes. No new prompt means the program is still running or waiting for input. Most programs explain themselves:

Bash / Zsh / PowerShell
uv --help # Most installed tools print their usage with --help

For built-in commands, use man ls on macOS and Linux (press q to quit), or Get-Help ls in PowerShell.

C. Navigate the file system

A shell is always in exactly one folder, the current working directory. Commands read and create files there unless you give another location. Most “file not found” errors mean the shell is in a different folder from the one you expected. These commands work in Bash, Zsh and PowerShell:

Bash / Zsh / PowerShell
pwd # Print the current working directory
ls # List what is inside it
cd ~ # Go to your home folder
cd Documents # Enter a folder inside the current one
cd .. # Go up to the parent folder

A path names a location. An absolute path starts from the top of the disk, such as /Users/alex/Documents on macOS or C:\Users\alex\Documents on Windows. A relative path starts from the current folder, such as Documents or ../Downloads. Three shortcuts appear everywhere:

ShortcutMeaningExample
~Your home foldercd ~
.The current folderopen . (macOS)
..The parent foldercd ..

Connect the terminal to the folders you already know: open the current folder in your file manager and compare it with the output of ls.

Bash / Zsh · macOS & Linux
open . # macOS: open the current folder in Finder
xdg-open . # Linux: open the current folder in the file manager
ls -a # Also list hidden names that start with a dot, such as .venv
PowerShell · Windows
explorer . # Open the current folder in File Explorer
ls -Force # Also list hidden items, such as .venv

Paths with spaces

The shell splits a command at spaces, so cd School Stuff asks for a folder named School with an extra argument Stuff. Put such paths in quotes. Pressing Tab to complete a name also adds the correct quoting for you.

Bash / Zsh / PowerShell
cd "School Stuff" # Quote a folder name that contains a space

For new course folders, prefer names without spaces, such as cs301-notebooks.

D. Work with files

These commands also work in all three shells. Each one acts on the current folder unless you give a path.

CommandWhat it does
mkdir archiveCreate a folder named archive
cat notes.txtPrint a text file
cp notes.txt copy.txtCopy a file
mv copy.txt archive/Move a file into a folder (also renames: mv a.txt b.txt)
rm copy.txtDelete a file (a folder needs extra options, shown in G)
clearClear the screen; nothing is deleted
rm skips the Trash

Files deleted with rm do not go to the Trash or Recycle Bin and usually cannot be recovered. Check pwd and the file name before you press Return. When unsure, delete in Finder or File Explorer instead.

E. How the shell finds programs

When you type uv, the shell does not search the whole disk. It checks the folders listed in an environment variable called PATH, in order, and runs the first matching program it finds. “command not found” (or “is not recognized” in PowerShell) means that no folder on PATH contains that program: either it is not installed, or its folder has not been added to PATH in this terminal.

Bash / Zsh · macOS & Linux
echo $PATH | tr ':' '\n' # Show the PATH folders, one per line
which python3 # Show which python3 the shell would run
PowerShell · Windows
$env:Path -split ';' # Show the PATH folders, one per line
Get-Command python # Show which python the shell would run

It is fine if Python is not found yet; uv installs one in step 3. On Windows, a python that opens the Microsoft Store is only a placeholder, not a real Python. In this course, run Python through uv run python.

Why installers say “reopen the terminal”

A shell reads its startup file once, when it starts: ~/.zshrc for Zsh, ~/.bashrc for Bash, and the file named by $PROFILE in PowerShell. Installers such as uv and mise add their folders to PATH by editing these files or your user settings. A terminal that was already open does not see the change, so open a new one. Restart your IDE too, because its built-in terminal inherits the environment from when the IDE started.

What a virtual environment changes

A project's .venv folder contains its own python and installed packages. “Activating” an environment mainly puts .venv/bin (.venv\Scripts on Windows) at the front of PATH, so python finds the project's interpreter first. uv run does the same for a single command, which is why this guide never asks you to activate. When a package seems to be missing, the first question is always: which Python is running? The sys.executable checks in step 3 answer it.

F. Everyday habits

  • Tab completes file, folder and command names. Use it instead of typing long paths.
  • Up arrow recalls earlier commands, so you can fix a typo and rerun.
  • Ctrl+C stops the running program and returns the prompt, on every system including macOS. To copy text, use Cmd+C on macOS, Ctrl+Shift+C on Linux, or select text and press Ctrl+C in Windows Terminal. Paste with Cmd+V, Ctrl+Shift+V or Ctrl+V respectively.
  • Run one command at a time while you learn, and read its output before the next one. An error in the first command often makes every later command fail.
  • Read errors from the bottom. The last lines usually name the problem. When asking for help, copy the full command and output as text, together with the output of pwd.
  • A prompt of > or quote> on its own means you left a quote or bracket open. Press Ctrl+C and retype the command.

Three prompts that look alike

You seeYou are inType here
%, $, or PS …>The shellCommands such as cd, uv, java -version
>>>Python's interactive promptPython code only. Type exit() to return to the shell.
A notebook cellA notebook kernelPython or Java code for that notebook

Typing uv add … after >>>, or into a notebook cell, gives a syntax error, because Python is not a shell.

G. Practice before setup

Run these commands one at a time in a new terminal (Zsh users: enable comments first). Before pressing Return, predict what each one will print.

Bash / Zsh / PowerShell
cd ~ # Start in your home folder
mkdir terminal-practice # Create a practice folder
cd terminal-practice # Enter it
pwd # Confirm where you are
echo "hello terminal" > notes.txt # Write a line of text into a new file
ls # You should see notes.txt
mkdir archive # Create a subfolder
cp notes.txt archive/copy.txt # Copy the file into the subfolder
ls archive # You should see copy.txt
cat archive/copy.txt # You should see hello terminal
cd .. # Go back to your home folder
  1. Open terminal-practice in Finder or File Explorer and confirm that it contains what ls showed.
  2. Check yourself: after the last command, what does pwd print, and why? Why would cat notes.txt fail there now?
  3. Open the folder in VS Code (File → Open Folder) and its terminal. Run pwd: the terminal starts in the folder you opened. Close VS Code before the next step.

Finally, delete the practice folder from your home folder. A folder needs two options: recursive (delete everything inside it) and force (do not ask about each file). PowerShell spells them out instead of accepting -rf:

Bash / Zsh · macOS & Linux
pwd # Check that you are in your home folder, not inside terminal-practice
rm -rf terminal-practice # Delete the folder and everything inside it
PowerShell · Windows
pwd # Check that you are in your home folder, not inside terminal-practice
rm -Recurse -Force terminal-practice # Delete the folder and everything inside it

Run ls to confirm it is gone. rm -rf deletes immediately, without the Trash and without asking, so always run pwd and read the folder name first. A wrong path deletes the wrong folder.

If you can do this without looking back, you have the terminal skills the setup below assumes.

Keep course tools separate from system software

Use uv as the Python version, environment, and package manager for this recitation. You do not need to install Python separately before installing uv. uv-managed Python installations live in a managed user directory; course packages belong in the project's .venv.

One project, one environment

Follow the uv commands below instead of installing course packages into an operating-system Python or an unrelated application's Python. Keep notebook files beside pyproject.toml, outside .venv. Use uv add for dependencies and uv run for project commands; no manual environment activation is needed.

Your IDE provides the notebook interface; a kernel executes a notebook's code. Python and Java need different kernels. Open .ipynb files directly in VS Code or PyCharm with notebook support enabled. You do not need to start JupyterLab separately. If you do not use a notebook-capable IDE, follow the optional JupyterLab section for a browser interface. Notes stay on this website; the Recitation 1 page offers downloadable Python and Java exercise notebooks alongside its browser exercises.

Each code block labels the intended shell or notebook language. The text after # (or // in Java) briefly explains the command; it is a comment and can be copied with the code.

Run terminal commands in your terminal, not in a notebook cell or a Python >>> prompt (see three prompts that look alike). Windows instructions use PowerShell. Installer downloads need an internet connection. In Zsh, enable # comments first in every new terminal.

1. Install uv before Python

macOS / Linux

Bash / Zsh · macOS & Linux
curl -LsSf https://astral.sh/uv/install.sh | sh # Install uv with the official installer

Windows — PowerShell

PowerShell · Windows
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex" # Install uv in Windows PowerShell

Close and reopen the terminal after installation so the updated user PATH is available. Then check:

Bash / Zsh / PowerShell
uv --version # Check that uv is available

Use one uv installation method. If you already have a working uv installation, verify its version and continue. The Windows installer command applies its execution-policy option to that installer process; you do not need to change the machine-wide PowerShell policy.

2. Create and enter your notebook folder

This step creates a normal working folder, not a virtual environment. Use pwd and cd (see Navigate the file system) to move to the parent location where you want to keep your course notebooks, then run these two commands:

Bash / Zsh / PowerShell
mkdir cs301-notebooks # Create the notebook working folder
cd cs301-notebooks # Enter the working folder

If this folder already exists, skip mkdir and enter it with cd. All commands in the next step run inside this folder. The .venv directory is created separately by uv.

3. Install Python and create the course environment with uv

Run these commands inside the cs301-notebooks folder created in the previous step. They work in Bash, Zsh and PowerShell.

Bash / Zsh / PowerShell
uv python install 3.13 # Install a uv-managed Python 3.13
uv init --bare --python 3.13 # Create the project metadata
uv python pin 3.13 # Record Python 3.13 for this project
uv venv --python 3.13 --managed-python # Create .venv with managed Python
uv add jupyterlab ipykernel # Add notebook tools to the project environment

uv python install obtains a managed Python. uv init creates project metadata, and uv python pin records the chosen version in .python-version. The explicit --managed-python option ensures the virtual environment uses a uv-managed interpreter. uv add records dependencies in pyproject.toml, resolves them in uv.lock, and installs them into .venv.

The package setup includes JupyterLab as an available browser interface; starting it is optional. IDE users can continue directly with kernel setup below.

Register and check the Python kernel

Stay in cs301-notebooks for these commands. The kernel registration is scoped to the project environment rather than a global kernel directory.

Bash / Zsh / PowerShell
uv run python -m ipykernel install --sys-prefix --name cs301-python --display-name "Python (CS301)" # Register the project Python kernel
uv run jupyter kernelspec list # List kernels visible to this project
uv run python -c "import sys; print(sys.executable)" # Show the project Python executable

The interpreter path should point inside this project's .venv. Open cs301-notebooks in your IDE and create or open a Python notebook. Select the project's .venv Python interpreter (or Python (CS301) where listed) as its kernel. In VS Code, enable the Microsoft Python and Jupyter extensions and use Select Kernel; in PyCharm, select the project interpreter and its notebook kernel. Run this notebook cell with Shift+Enter:

Python · notebook cell
import sys # Load Python runtime information
print(sys.executable) # Check which Python this notebook uses
print(1 + 1) # Verify that the Python cell prints 2

Check that the notebook also uses the project's .venv and prints 2. In later sessions, reopen the project folder and notebook in your IDE. To add a package, use uv add package-name, replacing the example name with the actual dependency.

4. Check your existing Java JDK

CS201 normally already gives you a JDK. Keep using it if its major version is at least 17 (17 or newer); you do not need to install another JDK or mise for this course. JDK 21 is one suitable example. Check in your IDE's terminal:

Bash / Zsh / PowerShell
java -version # Check the active Java runtime version
javac -version # Check that the JDK compiler is available
java --list-modules # Look for the jdk.jshell module

Confirm that Java and the compiler use the intended JDK and the module list includes jdk.jshell. A JRE alone is not enough. If your existing JDK meets these checks, skip the optional mise section and go directly to Java kernel installation.

5. Optional: install a global JDK with mise

If you have no JDK, or yours is older than version 17, use mise to install a Microsoft JDK as your global default. Choose version 17, 21, or 25; the example below uses 21. A global selection makes java and javac available directly in an activated shell, without a mise exec prefix.

macOS — default Zsh shell

Zsh · macOS
curl -fsSL https://mise.run/zsh | sh # Install mise and configure Zsh activation

Linux — Bash shell

Bash · Linux
curl -fsSL https://mise.run/bash | sh # Install mise and configure Bash activation

The shell-specific installers add mise activation to that shell's startup file. Open a new terminal afterward. For other shells, follow the official mise shell-setup instructions linked below.

Windows — PowerShell

PowerShell · Windows
winget install jdx.mise # Install mise on Windows

Open a new PowerShell window after installation, then add mise activation to your PowerShell profile. If winget is unavailable, use an alternative from the official mise installation guide.

PowerShell · activate mise
if (-not (Test-Path $PROFILE)) {
    New-Item -ItemType File -Path $PROFILE -Force | Out-Null # Create the profile if needed
}
$activation = '(&mise activate pwsh) | Out-String | Invoke-Expression'
if (-not (Select-String -Path $PROFILE -SimpleMatch $activation -Quiet)) {
    Add-Content $PROFILE $activation # Add the activation line once
}

Open another new PowerShell window so the profile takes effect. Shell activation is required for the global JDK to appear on PATH and for mise to set JAVA_HOME.

Select a global Microsoft JDK — all platforms

In a terminal where mise is activated, run:

Bash / Zsh / PowerShell
mise --version # Check that mise is available
mise use --global java@microsoft-21 # Install Microsoft JDK 21 as the global default
# You may instead choose java@microsoft-17 or java@microsoft-25

mise use --global installs the selected JDK and records it in your global mise configuration rather than the course project's mise.toml. Open a new terminal after changing the global selection, then check the JDK directly:

Bash / Zsh / PowerShell
java -version # Check the global Java runtime version
javac -version # Check the global JDK compiler
java --list-modules # Check the global JDK for jdk.jshell

The version output should identify Microsoft and the major version you selected. In later sessions, use ordinary java, javac, and notebook tools; no mise exec -- prefix is needed.

6. Install the Java kernel inside the uv environment

  1. Complete the uv project setup first. Shut down any running notebook kernels or IDE-managed Jupyter server before installing a new kernel.
  2. Download the binary distribution ZIP from the IJava releases page, not the source-code ZIP.
  3. Extract it inside cs301-notebooks. Keep the extracted folder name, such as ijava-1.3.0; you do not need to rename it. Ensure that folder directly contains both install.py and the java folder; move them out of an extra nested directory if necessary.

Install and check the kernel — all platforms

Start in cs301-notebooks using a terminal where your existing or globally mise-managed JDK is available. Keep only one directory whose name starts with ijava in this project folder so cd ijava* selects it unambiguously. If you keep multiple versions, use the exact folder name instead, for example cd ijava-1.3.0. The installer runs from its own directory, while --project .. selects the parent uv project and its Python environment:

Bash / Zsh / PowerShell
cd ijava* # Enter the extracted folder, including names such as ijava-1.3.0
uv run --project .. python install.py --sys-prefix # Install the Java kernel into the parent project environment
cd .. # Return to the notebook project folder
uv run jupyter kernelspec list # List kernels visible to this project

The kernel list should include java. Open the Java notebook in your IDE and select Java as its Jupyter kernel, using the course project environment. For PyCharm, use a managed Jupyter server with the project interpreter to select a non-Python kernel. A Python interpreter alone cannot execute Java cells. If Java is not listed, see Common setup problems. Run this cell:

Java · notebook cell
System.out.println(System.getProperty("java.version")); // Check the Java version used by the notebook
System.out.println(1 + 1); // Verify that the Java cell prints 2

Check for a JDK major version of at least 17 and a final output of 2. IJava uses JShell-style interactive execution; this simple test needs no Main class wrapper.

7. Daily notebook workflow

  1. Open cs301-notebooks in VS Code or PyCharm. Open the notebook directly in the IDE; no separate JupyterLab launch is needed. If you do not use a notebook-capable IDE, use the optional browser workflow.
  2. Open the appropriate language notebook when exercises are released. Select the project's .venv Python kernel (shown as Python (CS301) where available) or Java to match its code; changing kernels does not translate a program.
  3. Run cells from top to bottom with Shift+Enter. Save edits and outputs with Ctrl+S or Cmd+S.
  4. Restart the kernel and run all cells before checking or sharing results. Unlike this website's temporary editors, notebook files can retain your edits.

Optional: use JupyterLab in a browser

Use this section if you do not have a notebook-capable IDE, do not want to use one, or prefer the browser interface. If your notebook already runs in your IDE, skip this section.

After completing the environment and kernel setup above, enter cs301-notebooks in a terminal where your JDK is available if you use Java. Run:

Bash / Zsh / PowerShell
uv run jupyter lab # Start the optional browser interface from the project
  1. Keep the terminal running. If a browser tab does not open automatically, open the local URL printed in the terminal.
  2. Open the downloaded notebook, or create a new notebook. Select Python (CS301) for Python or Java for Java, then run the verification cell above for that language.
  3. Follow the same daily workflow: run cells in order, save your notebook, and restart the kernel and run all cells before sharing.
  4. When finished, save your notebook and stop JupyterLab with Ctrl+C in its terminal; confirm shutdown if prompted. Closing the browser tab alone does not stop the server.

For the next session, return to the project folder and run the same launch command.

Common setup problems

  • uv or mise not found: reopen the terminal after installation so it rereads its startup files, then check your PATH as shown in How the shell finds programs. Use the official setup guide for your shell.
  • No such file or directory: run pwd and ls to check that you are in the folder the instructions expect; quote paths that contain spaces.
  • Wrong Python or missing package: enter the course project, use uv run python, and add dependencies with uv add. Check sys.executable inside the notebook.
  • Kernel missing: use uv run jupyter kernelspec list in the same project where you installed it. In your IDE, select the course project interpreter or managed server. If the project-local Java kernel is still not detected, use the optional JupyterLab workflow to access it from the same environment. Avoid launching an unrelated system Jupyter.
  • Java kernel fails: verify the JDK version, compiler, and jdk.jshell in your IDE's terminal or the terminal used for the optional browser workflow. Restart your IDE after changing the JDK so it inherits the updated environment. mise users should also run mise doctor and confirm that shell activation is enabled.
  • Need help: bring your OS, shell, version outputs, selected kernel and exact error message to the TA.
